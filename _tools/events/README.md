# 행사 목록 만들기 — «이번 주말 어디 갈까»

앱 홈의 «🎪 이번 주말 어디 갈까» 카드와 행사 화면이 읽는 `assets/events.json`을 만드는 도구입니다.
공공 기관이 공개한 행사 자료를 모아 **파일 하나**로 두고, 앱은 그 파일만 받아 **폰 안에서** 아이 개월·지역으로 거릅니다.
아이 정보도 지역 선택도 밖으로 나가지 않습니다.

## 자료 (열쇠가 있는 곳만 씁니다)

| 환경변수 | 자료 | 어디서 받나 | 비고 |
|---|---|---|---|
| `SEOUL_KEY` | 서울시 문화행사 정보 (`culturalEventInfo`) | data.seoul.go.kr → 로그인 → 인증키 신청 (즉시) | 매일 갱신, «이용대상» 글로 나이를 읽음 |
| `DATA_GO_KR_KEY` | 전국공연행사정보 표준데이터(입장연령 있음) · 전국문화축제 표준데이터 | data.go.kr → 로그인 → 두 자료 «활용신청» (자동승인) → 마이페이지의 일반 인증키 | 분기 갱신(매월 초 취합) — 느리지만 전국 |
| `DATA_GO_KR_KEY` (같은 열쇠) | 한국관광공사 국문 관광정보 KorService2 — 행사정보(`searchFestival2`) + 소개정보(`detailIntro2`: 관람 연령·요금·홈페이지) | data.go.kr → «한국관광공사_국문 관광정보 서비스_GW» 활용신청(개발계정 자동승인, 2026-11-02) | 기능마다 하루 1,000회 — 소개정보는 한 번에 450건까지. 출처 이름 `tour` |
| `KOPIS_KEY` | 공연예술통합전산망 KOPIS — 아동 공연(`kidstate=Y`) | kopis.or.kr → OPEN API → «인증키 발급신청»: **회원가입 없이** 이름·이메일·서비스목적·신청자 구분(개인 가능)·소재지 → 인증키가 이메일로 옴(1인 1개) | 상세에서 관람연령·가격·예매처. **출처 표시 의무**: «(재)예술경영지원센터 공연예술통합전산망(www.kopis.or.kr)» — 앱 행사 화면 아래에 자동으로 붙음. 1초에 10회를 넘기면 서비스 중지 → 상세는 둘이서 0.3초 간격 |

열쇠는 저장소 **Settings → Secrets and variables → Actions → New repository secret**에 위 이름 그대로 넣습니다.
공공데이터포털 열쇠는 «일반 인증키(Decoding)» 값을 넣어도 되고 Encoding 값을 넣어도 됩니다(둘 다 알아서 처리).

## 돌아가는 때

`.github/workflows/events.yml` — **월·목 06:00(KST)** 자동, 또는 Actions 탭에서 «Run workflow».
바뀐 것이 있으면 봇이 `assets/events.json`을 커밋하고 홈페이지(Pages) 재배포를 요청합니다.
열쇠가 하나도 없으면 아무것도 하지 않고 성공으로 끝납니다(실패 메일이 가지 않게). 열쇠가 있는데 자료를 하나도 못 받으면 실패로 끝나고 옛 파일은 그대로 둡니다.

## 거르는 규칙 (fetch.mjs)

- 기간: 어제 ~ 60일 뒤. 그 밖은 뺍니다.
- 아이 앱이므로 **만 7세(84개월) 이상 전용**은 뺍니다. 술·성인·세미나·채용 같은 행사도 뺍니다(`NO_WORDS`).
- 아이를 데리고 가는 나들이가 아닌 것도 뺍니다(`notForKids`): 북토크·강연·인문학·아카데미·창업·시민대학·정규강좌·졸업전시·영화제·온라인 전시·찾아가는 교육·학급/어린이집 **단체** 전용·외국인 대상·전문가 대상·회원 전용·부모만 듣는 강연(«자녀를 둔 학부모», «양육자 대상»). 2026-11-02 첫 서울 자료에서 이런 것이 «누구나»로 섞여 들어와 고쳤습니다.
- 행사마다 **아이 맞춤 점수 `kid`**를 붙입니다: 3 = 아이 나이를 콕 집음(예: 8~16개월, 6~9세, 36개월 이상), 2 = 이름에 어린이·유아·가족·그림책·인형극·아이 캐릭터 이름 등, 1 = 누구나·만 5세 이상, 0 = 모름 또는 «초등학생 이상»처럼 어린아이를 막는 일반 공연. 앱은 2·3을 먼저 보여 주고 0·1(«누구나 갈 수 있는 행사»)은 «더 보기» 뒤에 접습니다.
- 이름만 봐서는 무슨 행사인지 모르는 것(«2026년 11월 공연 (1회)», «○○아트홀 기획공연», «11월 문화프로그램 안내»)과 «운영 안내»·«휴관» 공지는 뺍니다.
- 날짜를 몰라 1월 1일~12월 31일로 채워 둔 전국 자료, «2626년»처럼 연도가 틀린 날짜는 뺍니다.
- 관광공사 행사는 석 달 전 시작분부터 받아(진행 중인 축제 포함) 기간으로 다시 거르고, 소개정보의 «관람 가능 연령»을 개월로 읽습니다. 비어 있으면 «연령 제한 표기 없음»(누구나). 홈페이지 칸이 `<a href>` 꼴이면 첫 주소만 씁니다. 소개정보를 못 받은 행사는 연령 표기 없음으로 남기고, 실행 요약 메모에 몇 건인지 적습니다.
- 주소가 «전남 동구»처럼 들어온 것은 광주로, «충남 유성구»는 대전으로 바로잡습니다(전남·충남 주소에는 «구»가 바로 오지 않음).
- 전국 공연 자료(공공데이터포털)는 «전체관람가» 어른 공연이 많아, 나이를 콕 집었거나 이름·소개에 아이와 갈 만한 낱말이 있을 때만 남깁니다.
- 연령은 주최 표기를 개월로 읽습니다(`parseAge`, 자가 점검 100건(나이 읽기 76건 포함): `EV_SELFTEST=1 node _tools/events/fetch.mjs`). 못 읽으면 비워 두고 앱이 «연령 표기 없음»으로 보여 줍니다.
- 요금은 «무료/유료/표기 없음»만 가립니다(«10,000원»의 0원에 속지 않음).
- 제목·장소·날짜·링크는 자료 그대로. 링크는 http(s)만. HTML 태그는 벗깁니다.
- 같은 행사는 하나로 묶습니다: «2026»·«제25회»·«(1회)»를 뗀 이름과 시·도가 같고 날짜가 겹치거나 바로 이어지면 같은 행사로 보고, KOPIS → 서울시 → 한국관광공사 → 공공데이터포털 순으로 하나만 남겨 날짜를 합칩니다(«구미라면축제»와 «2026 구미라면축제», 이틀 연달아 올린 같은 공연).

## 흐름만 점검하기 (열쇠 없이)

```
EV_MOCK=1 SEOUL_KEY=x DATA_GO_KR_KEY=y KOPIS_KEY=z node _tools/events/fetch.mjs --out /tmp/events.json
```
지어낸 응답(제목에 «예시»)으로 전 과정을 돌려 파일 꼴을 확인합니다. 실제 자료가 아니니 저장소에 올리지 않습니다.

## 파일 꼴

```json
{"updated":"2026-11-03","window":["2026-11-02","2027-01-02"],"sources":{"seoul":{"ok":true,"n":120}},"count":1,
 "events":[{"src":"seoul","id":"seoul:abc","title":"…","place":"…","sido":"서울","gu":"강서구","start":"2026-11-08","end":"2026-11-09",
   "ageMin":12,"ageMax":null,"ageText":"만 12개월 이상","free":true,"fee":null,"url":"https://…","img":null,"kind":"체험"}]}
```
`check.mjs`(앱 자동 점검)가 이 파일의 꼴·링크·연령·지난 행사 여부를 검사합니다.
